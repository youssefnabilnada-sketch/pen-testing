## مطلوب من مالك Oracle: خطوة واحدة للبدء (قراءة فقط)

افتح SSH المعتاد إلى Oracle باستخدام مفتاحك الخاص، بدون مشاركة المفتاح أو أي بيانات دخول. داخل طرفية Ubuntu استخدم:

```bash
cd /srv/aegis && sudo python3 scripts/oci-acceptance-readonly.py
```

إذا لم يكن الملف موجودًا أو ظهرت رسالة خطأ، **لا تُعد تثبيت المشروع أو تنفذ ملفات إعداد جديدة من تلقاء نفسك**. أخبرنا فقط باسم الخطأ دون محتوى أي ملف `/etc/aegis`.

هذا الفحص مُصمم لعدم تغيير قاعدة البيانات أو إرسال بريد أو إجراء فحص مواقع. راجع أنه إصدار حديث من السكريبت؛ في النسخة الجديدة، GET غير المسجل لـ`/auth/me` يجب أن يرجع 401، و`/auth/firebase/config` يرجع 200، وتظل العمليات الأخرى محمية بـ503. إن كانت نسخة السيرفر لا تزال أقدم، لا تستنتج عطلًا من اختلاف التوقعات.

**شارك فقط** سطور `PASS` / `CHECK` والخط النهائي `AEGIS_ACCEPTANCE_...` بعد مراجعتها. **لا تشارك** مفاتيح SSH، كلمات المرور، كود البريد، ملفات env، JWT، API tokens أو مخرجات `journalctl` الكاملة.

## بعد نجاح فحص Oracle

1. Firebase Console: Authentication → Sign-in method: تأكد أن موفّر تسجيل الدخول المطلوب مفعّل؛ Settings → Authorized domains: سجّل فقط نطاق Preview ثابتًا ومصرّحًا به بعد اختياره، من غير إضافة نطاقات عشوائية. فعّل Google فقط إن كانت التجربة تحتاجه.
2. Brevo: Transactional → Logs: تحقق من آخر تجربة بريد مصرّح بها، وأن النتيجة Delivered أو افحص السبب إذا ظهرت Deferred / Blocked / Bounce. تحقق من وصول الرسالة للصندوق الفعلي؛ Delivered وحدها ليست ضمان Inbox.
3. تفعيل مسارات المصادقة المحمية على Oracle يجب أن يظل تحت اختبار Preview محدود ومؤقت، وفق وثيقة `RELEASE-READINESS-2026-10-31.md`. لا ترسل سر الـGateway عبر المحادثة أو GitHub، ولا تضعه في `NEXT_PUBLIC_*`.
4. راجع Cookie / CSRF / Session في المتصفح مع حساب تجريبي فقط. إغلاق الاختبار يعيد Gateway إلى وضع الحظر.
5. **لا تغيّر Alias الإنتاج أو تفعّل scheduler أو تفتح تسجيل العملاء** قبل اكتمال مهام Astra 4–8 وقبول الاختبارات الشاملة وموافقة نهائية على الإصدار.
