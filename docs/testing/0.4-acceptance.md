# Firebase UI integration acceptance
- Google and email/password flows use official Firebase SDK with in-memory persistence.
- No Firebase token persists in localStorage or database; sign out SDK after exchange.
- Existing local login, account data, organizations and asset authorization remain intact.
- New Firebase registration is explicit, requires verified/recent identity, sets an AEGIS
  recovery password, creates no memberships or asset grants. Existing emails never auto-link.
- Linking requires local session + CSRF + current password. Unlink requires reauthentication.
- Missing configuration hides external login; errors are visible without token disclosure.
- Tests cover new/duplicate accounts, link conflicts, stale/unverified identity, CSRF,
  revoked-token adapter failure, UI errors/success, persistence cleanup, existing regression.
- Live Google consent and provider delivery remain blocked until operator credentials
  are configured; deterministic tests cannot stand in for that acceptance.
